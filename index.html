대표 프로젝트: 문제를 만나고, 측정하고, 고친 과정

GitHub 저장소의 개발 일지와 Notion 기획서를 바탕으로 정리했습니다. AI(Claude)와 함께 만들었고, 무엇을 맡기고 무엇을 직접 판단했는지도 적었습니다.

증강 오목 (Augmented Omok) · 2~4인 파티게임

진행 중 · Unity C#

오목을 두다가 10/20/30번째 턴마다 증강(특수 능력) 22종 중 하나를 골라 쓰는 게임입니다. 기획서(Notion v0.3, v0.3.1)를 쓰고, 친구 의견을 반영해 고치고, 구현 현황 보고서로 기획 대비 진행도를 항목별로 점검하며 개발하고 있습니다.

1 자리 불균형

문제 청소부가 항상 마지막 순서 플레이어 바로 뒤에 움직여, 4인전에서 첫 자리 승률 70%, 마지막 자리 3%까지 벌어졌습니다.
개선 청소부마다 움직이는 박자를 무작위로 하고 출근 시각도 흔들었습니다.
결과 4인 1000판 측정에서 자리별 승률이 22.9 / 22.7 / 27.9 / 26.2%로 25% 근처에 모였습니다.

2 증강 밸런스

문제 쌍수, 저격수, 도박꾼의 주사위가 단독 순승률 +17~22%로 너무 셌습니다.
개선 봇 시뮬레이션 수치를 근거로 사용 횟수를 줄이고(쌍수 2→1회 등) 나눠서 조정했습니다.
결과 증강 단독 순승률 범위가 약 -19% ~ +12%로 좁아졌습니다. 4인 전원 증강 1000판에서는 쌍수 35.3%, 지진 15.8%로 아직 편차가 있어 조정안을 정리해 두었습니다.

3 측정 도구의 오류

문제 시뮬레이션의 "청소부 ON"이 자동 출근까지 켜서 실제 기본값(꺼짐)과 달랐고, 그래서 청소부 관련 증강 5개의 수치를 믿을 수 없었습니다.
개선 결과를 그대로 쓰지 않고 원인을 찾아 일지에 적고, 기준 수치를 다시 잡는 일을 첫 할 일로 올렸습니다.
결과 수치를 한 번에 다 바꾸지 않고 "측정 → 하나씩 적용 → 재측정" 순서로 진행합니다. 규칙 자동 테스트 84개는 모두 통과합니다.

AI와 내 판단: 승률을 "+13%" 같은 순승률이 아니라 실제 승률(%)로, 4명 모두 증강을 가진 실제 조건과 자리별 구성까지 보여 달라고 요구해서 측정 방식을 바꿨습니다. 증강 효과는 시스템이 아니라 플레이어가 직접 선택해 쓰는 것으로 기획을 확정했습니다.

다음 단계: 청소부 기본값으로 4인 1000판 재측정, 조정안을 나눠 적용 후 재측정, 친구 플레이 피드백 수집.

과제 6 → 7 · Supabase

내가 세운 계획과 실제로 한 일을 나란히 적고, 차이를 돌아보며 다음 계획을 고치는 웹 다이어리입니다. 6번에서 만들고 7번에서 로그인을 붙였습니다.

1 보이지 않던 습관

문제 할 일을 체크하는 앱은 많지만, 내가 계획을 어느 쪽으로 자주 틀리는지는 보이지 않았습니다.
개선 계획과 실제 기록을 나란히 두고 차이(실제 − 예상)를 돌아보기에서 보여주게 했습니다. 수정 이력이 남고, 같은 기록을 두 번 저장해도 1건만 남습니다.
결과 계획 → 실제 → 돌아보기 → 다음 계획으로 이어지는 흐름을 완성했고, 자료는 JSON 파일로 내려받을 수 있습니다.

2 누구나 볼 수 있던 자료

문제 6번은 링크를 아는 사람이면 누구나 내 계획을 보고 고칠 수 있었습니다.
개선 Supabase Auth로 가입·로그인을 붙이고, 표 직접 접근 권한을 모두 회수해 DB 함수 안에서 auth.uid()로 주인을 확인하게 했습니다. 로그아웃하면 서버가 세션을 지워 이전 토큰을 거절합니다.
결과 직접 만든 확인 스크립트 29개 항목 통과. 남의 자료 읽기·수정·삭제는 404, 로그인 없이 요청은 401, 로그아웃 뒤 같은 토큰은 401로 거절됩니다.

3 쓰면서 발견한 실수

문제 5일 기록을 직접 쓰다가 기록 순서(규칙 변경 전에 3일차 기록)를 두 번 틀렸습니다.
개선 사람이 조심하는 대신 서버가 순서를 강제하게 했습니다. 규칙을 바꾸기 전에는 새 날짜 기록을 거절하고 안내 문구를 보여줍니다.
결과 같은 실수를 앱이 막아 주고, 변경 전후를 같은 지표·단위로 비교한 표가 자동으로 나옵니다.

AI와 내 판단: AI는 새 Supabase 프로젝트와 별도 서버(Python, Cloudflare)를 제안했지만, 기존 프로젝트 안의 별도 칸과 GitHub 링크로 열리는 정적 방식을 제가 선택했습니다. 5일 기록 주제도 AI 후보 대신 제가 공부 중인 네트워크로 정했습니다.

01. 배려와 소통을 통한 신뢰 구축

STAR 01
상황

학원에 등록한 지 약 일주일 차로, 새로운 환경과 커리큘럼에 적응하느라 동료들 모두가 여러모로 바쁘고 긴장해 있는 상황이었습니다.

행동

모르는 부분이 생기면 주저하지 않고 동료들에게 친절하게 질문을 던졌고, 동료들이 알려준 내용을 단순히 받아들이는 데 그치지 않고 AI를 활용해 제가 이해한 방식과 저만의 스타일로 재정리하여 다시 동료들과 공유했습니다.

결과

동료들로부터 "모르는 것을 적극적으로 물어보고, 본인만의 방법으로 잘 정리해서 알려줘서 고맙다"는 긍정적인 평가를 받았으며, 이를 통해 학원 내에서 빠르게 신뢰를 쌓고 돈독한 관계를 형성할 수 있었습니다.

• 0으로 나누기, 공백 입력, 비정상 문자열 등 5대 엣지 케이스 테스트 100% 통과
