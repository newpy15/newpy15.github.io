플랜두씨 다이어리 2 · 로그인과 내 자료 보호

과제 7
문제

6번 앱은 링크를 아는 사람이면 누구나 내 계획을 보고 고칠 수 있었습니다.

개선

Supabase Auth로 가입·로그인을 붙이고, 표 직접 접근 권한을 모두 회수한 뒤 DB 함수 안에서 auth.uid()로 주인을 확인하게 바꿨습니다. 로그아웃하면 서버가 세션을 지워 이전 토큰이 바로 거절되게 했습니다. 5일 기록에서 순서를 두 번 틀린 뒤에는 서버가 순서를 강제하는 규칙을 추가했습니다.

결과

직접 만든 확인 스크립트 29개 항목 통과(0 실패). 다른 계정의 자료 읽기·수정·삭제는 모두 404, 로그인 없이 요청하면 401, 로그아웃 뒤 같은 토큰은 401로 거절됐습니다.

AI와 내 판단: AI는 새 Supabase 프로젝트를 만들자고 했지만, 같은 프로젝트 안의 별도 칸(diary2)을 쓰기로 제가 바꿨습니다.

플랜두씨 다이어리 · 계획과 실제의 차이 보기

과제 6
문제

할 일을 체크하는 앱은 많지만, 내가 계획을 어느 쪽으로 자주 틀리는지는 보이지 않았습니다.

개선

계획과 실제 기록을 나란히 두고 차이(실제 − 예상)를 돌아보기에서 보여주게 했습니다. 계획을 고쳐도 수정 이력이 남고, 같은 기록을 두 번 저장해도 1건만 남도록 했습니다. 돌아보기 결과는 다음 계획에 넘길 한 줄로 적습니다.

결과

계획 → 실제 → 돌아보기 → 다음 계획으로 이어지는 흐름이 Supabase에 저장되어 기기를 바꿔도 유지되고, 내 자료를 JSON 파일로 내려받을 수 있습니다.

AI와 내 판단: AI가 제안한 별도 서버 방식(Python 서버, Cloudflare)은 GitHub 링크로 열리는 방식과 맞지 않아 따르지 않았습니다.

T05
문제

개선

문제

결과

미리보기와 다운로드가 같은 렌더 로직을 쓰고, 설치 없이 HTML 한 파일로 동작합니다.

01. 배려와 소통을 통한 신뢰 구축

STAR 01
상황

학원에 등록한 지 약 일주일 차로, 새로운 환경과 커리큘럼에 적응하느라 동료들 모두가 여러모로 바쁘고 긴장해 있는 상황이었습니다.

행동

모르는 부분이 생기면 주저하지 않고 동료들에게 친절하게 질문을 던졌고, 동료들이 알려준 내용을 단순히 받아들이는 데 그치지 않고 AI를 활용해 제가 이해한 방식과 저만의 스타일로 재정리하여 다시 동료들과 공유했습니다.

결과

동료들로부터 "모르는 것을 적극적으로 물어보고, 본인만의 방법으로 잘 정리해서 알려줘서 고맙다"는 긍정적인 평가를 받았으며, 이를 통해 학원 내에서 빠르게 신뢰를 쌓고 돈독한 관계를 형성할 수 있었습니다.
